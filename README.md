# blacksailflow（黑帆）

一个入口统管整条工程工作流的超级智能体式（super agent 思路）工作流：主会话只负责掌控与拍板，具体工作交给常驻的执行单元，状态写进任务表而不是聊天记录。

名字取「黑帆」：黑帆船在海上只有一个船长下令，但船能开起来靠的是大副分工、水手干活和一本所有人都认的守则。这套运行时就是把这三件事固定成机制。

## 为什么需要它

单个会话做大型工程工作，会稳定地撞上四个问题：

1. **上下文被过程淹没**：读代码、跑测试、改文件的长输出全堆在主会话里，真正需要判断的信息被挤掉。
2. **责任边界模糊**：谁定目标、谁拆活、谁验收、谁交付混在一个上下文里，出错时说不清是哪一层的问题。
3. **状态散在文档里**：进度写在聊天、笔记或自述里，换会话就丢，重启后要人复述一遍。
4. **主会话被长命令和轮询卡住**：等一个构建、盯一个后台任务，主会话就只能原地打转，并发自然上不去。

结果就是：一个人干得越多，主会话越慢；想并行，没有地方放并行。

## 核心思路：单一入口掌控整条工作流

参照 super agent 的思路：**主会话只保留「掌控全局」这一件事**——定目标、切范围、派活、拍板、收结果；执行细节下放到下层，每层有自己的上下文、自己的职责和可核对的产出。

主会话因此不再被过程占用，可以在派活之后立即结束回合，等消息唤醒再处理下一件事。这是并发的前提：主入口不阻塞，下层才有并行空间。

## 三层怎么分工

- **captain**：只切群、派 mate、判群间冲突与拍板。不写文件、不阻塞；派完就结束回合，被消息唤醒再继续。
- **mate**：长期驻守一个任务群，对这个领域负责、跨版本持续。自己拆任务、派 hand、守验收；hand 交回后按验收标准核，不达标退回去重做。
- **hand**：领一件能独立验收的活，调查 + 改 + 测一次做完再交回，不做跨范围的顺手修改。

**群 = 领域，不是一次交付**：一个群对应一个长期责任范围，不是「这一版的需求」。群不随版本结束，mate 也不随单次交付退出。

## 在 DSH 上加强了什么

- **任务表是唯一状态源 + 可执行验收**：建任务、领取、流转、证据都走任务表工具；任务可绑定验收命令与工作目录，标记完成时自动执行，非零退出即拒绝完成并记录结果。对话和自述不算状态。
- **goal 派发 / 自动续轮 / 重启续跑**：goal 可以派给 teammate；回合结束后按 goal 状态自动续轮；宿主重启后重新装配，接着原目标继续。
- **三层身份与技能分层可见**：captain / mate / hand 各自注入对应的身份条款与工作方式正文；8 个技能按角色裁剪模型侧目录（captain 4 / mate 6 / hand 1）。
- **回合自检、自主循环、hand 折叠**：每回合按规则自检；回合结束后按任务表决定是否继续推进；已完成的 hand 输出折叠成标题，不再占用主会话上下文。

### 超高并发与效率

- 多 mate 并行：不同群由不同 mate 同时推进，互不阻塞。
- 每个 mate 下多 hand 并行：一个群里的活拆成互不重叠的几份，同时开工。
- captain 不阻塞：派完立即结束回合，不在主会话里等长命令。

### 通用 hook 修复了哪些 LLM 常见毛病

| 毛病           | 怎么注入/拦截                                                        |
| ------------ | -------------------------------------------------------------- |
| 防御性输出、无效复述   | 常驻规则正文（`hooks/resident-rules.md`）每轮注入，直接约束输出形态：只给结论、证据、未解决项    |
| 只读不写、看完就交回   | 回合自检规则要求「有活就落盘」；任务表验收命令保证「没改动就过不了验收」                           |
| 把自述当完成       | 任务表状态只认 `bf_*` 工具与验收命令退出码；自述、文档、聊天都不算状态                        |
| 循环卡死、反复试同一条路 | 常驻规则要求同一失败第二次前先改条件、连续三次无进展必须停手并给阻塞证据                           |
| 压缩后丢纪律       | 压缩后重锚：用同一个注入函数 + 同一份常驻规则重新锚定，不靠模型自己记住                          |
| 跨层通讯断裂、派完就断线 | 身份按档注入 + goal 派发/续轮 + 重启续跑；teammate 回合结束后仍可被 `send_message` 唤醒 |

### livefire 真实验证

不是跑单测就宣布完成：跟用户走同一条路线（真实仓库、真实浏览器、真实数据），走一遍用户会做的事，发现问题退回修，修完按同一路线复验，直到复验通过。cardplayer 那轮的 19/19 端到端判据、以及按同一路线复验后才收口的返工项，都是这么来的。

## 命名小巧思

- **黑帆海盗船（blacksailflow）**：整套工作流的名号；一个入口下令，全船执行。
- **captain / mate / hand**：船长管航向与拍板，大副守一个领域并分派，水手把一件活干完。
- **海盗守则**：三档共用的常驻规则正文。谁都要守同一本守则，换人不换规矩。
