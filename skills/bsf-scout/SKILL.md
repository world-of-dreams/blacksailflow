## 这技能是什么

只做一件事：**定位**。把现象变成「文件:行号 + 复现命令 + 排除记录」。
不做修复、不做验证、不做任务拆分。

## 什么时候用

- 验证不通过，但看不出问题在哪。
- 现象偶发，说不清触发条件。
- 要改一个模块，但不知道入口在哪。

能直接判断改哪的，不要先跑一遍定位。

## 怎么做

1. 现象写死：`在<条件>下，执行<操作>，得到<错误结果>，期望<正确结果>`。
2. 找入口：文件 + 行号 + 触发条件 + 一条能证明「确实走到这段」的复现命令（打印、日志、断点）。
3. 追链路：谁产生数据、谁中转、谁消费。每跳要能指出行号或配置项；指不出，这一跳就是断链。
4. 缺工具就造：能在 20 行内给出结论的小脚本，放 `tools/` 或 `.runtime/`；更大的换更小的探针。

## 记录（防止重走）

```
已确认：<结论>（证据：文件:行号）
已排除：<方向>（为什么排除：证据）
下一步：<最有希望的方向>
```

## 什么时候会用到别的 skill

- 定位发现需求本身矛盾 → **bsf-parrot**。
- 定位结论是「任务没拆清」→ 回原任务重拆。
