## 核心

任务写到 hand 看完不用再问「改哪里、变成什么样」，也不用你给步骤，就够。
hand 接任务后自己调查、实现、自测、交回；由同一个 hand 从头包到尾，不拆给第二个人接力。

## 任务写到什么程度

标准只有一条：**位置 + 行为**。

- 位置：能落到界面控件、文件或接口。
- 行为：操作之后发生什么。

示例（只是示例，按你的项目换）：`设置界面左下角加一个按钮，点击打开设置面板`。
不够：`优化设置模块`——不知道改哪。
过了：`先读 settings.ts，再抽一个 store……`——这是实现步骤，把 hand 的活干了。

再往下（先读哪个文件、抽什么抽象、用什么库）都是 hand 的判断。

## 粒度与顺序

- 一次改动尽量小到一轮能做完、能一眼看出改了什么，但要完整到 hand 一个人能交付。
- 有依赖按依赖排；能并行的先并行搭架子。
- 多个任务动同一处时，说清先后与约定，不因此并成一大块。

## 任务进任务表，派给 hand

- 每件事写进任务表：`bf_manifest_add`，acceptance 写可执行检查。
- 派活用 `subagent`，一个任务一个 hand；交回的证据用 `bf_manifest_update` 记到对应任务。
- hand 做自测；真实环境整链验证由 mate 用 bsf-livefire 跑，不交给 hand 当验收。

## 什么时候会用到别的 skill

- 拆的时候发现群边界不对（同一类任务被分到两个群、或某个群明显失衡）→ 把事实报给 captain，用 **bsf-chart** 判断是否重切；不自行改群。
- 用户对「这一版要什么」还有分歧 → **bsf-parrot**。
- 这一版到交付前 → 自己跑 **bsf-livefire**。
